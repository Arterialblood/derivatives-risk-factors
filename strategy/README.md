## 2. 设计哲学

### 2.1 "简单胜复杂" (Rayner Teo)

本策略的设计灵感来自 Rayner Teo 的核心思想：

> *"交易优势并不来自预测。它不是不断增加更多指标，也不是试图通过聪明的分析来战胜市场。真正的交易优势来自执行和风险管理。"*

策略刻意保持极简：
- **只看3类数据**：ETF日K线 (OHLCV)
- **只做2个动作**：买入科创50ETF / 轮动到中证1000ETF
- **只有1个止损规则**：2.5×ATR跟踪止损 或 -8%硬止损

### 2.2 "拥挤度即脆弱度" (沧海一土狗)

策略的信号设计来自对科技抱团跟踪的洞见：

> *"IV是行为一致性的温度计。高IV = 高仓位相似度 = 低多样性 = 高敏感度。"*

当市场拥挤（持仓高度趋同）时，任何外生冲击都会引发连锁赎回。本策略用6个维度的代理变量捕捉这种"拥挤→脆弱"的转变。

### 2.3 为什么从V1/V2升级到V3

| 版本 | 信号 | 回测收益 | 夏普 | 核心缺陷 |
|------|------|---------|------|---------|
| V1 | RV(20日) | -2.76% | -0.28 | ATR止损太紧(2×)，过早离场 |
| V2 | RV(20日) | +13.24% | 0.61 | **只用RV单维信号**，忽略了6个衍生品维度的交叉验证 |
| **V3** | **6维CSS** | **+47.34%** | **1.76** | 代理变量需用真实期权链数据替换 |

**V3的核心改进**：把6张图对应的6个衍生品风险指标，从"只看RV一个标量"升级为"6维z-score等权合成"，信号质量大幅提升。

## 3. 六大衍生品风险指标详解

这6个指标来自6张市场监控截图（IMG_0075 ~ IMG_0080），它们不是6个独立指标，而是**同一个"市场拥挤/脆弱"现象的6个观察窗口**。

### 3.1 ETF异常赎回压力 (IMG_0075)

| 属性 | 内容 |
|------|------|
| **对应因子** | `factor_06_etf_flow.py` |
| **原图** | ETF异常资金流向监控 |
| **信号含义** | ETF出现异常大额赎回，资金集中流出 → 现货端拥挤指标 |
| **触发条件** | ETF单日净流出 > 20日均值的2倍标准差 |
| **风险等级** | WATCH (1分) / ALERT (2分) |

**原理详解**：

ETF的申购赎回机制是ETF流动性的核心。当市场处于拥挤状态时（大量投资者持有相似仓位），一旦出现触发事件（如某只重仓股业绩暴雷），投资者会同时赎回ETF。这种"同步赎回"行为导致：

1. ETF做市商被迫卖出成分股来应对赎回
2. 成分股被抛售 → 指数下跌 → 更多赎回（正反馈循环）
3. ETF折价扩大 → 套利盘进场但流动性不足 → 波动放大

**为什么重要**：ETF异常赎回是"拥挤→崩溃"链条的第一个信号。它发生在期权市场反应之前，因为ETF是最直接的持仓工具。

**在V3中的代理变量**：`日内振幅 / 20日均值振幅`。当此比值 > 1.5 时，说明日内波动异常放大，可能源于流动性缺失或资金集中赎回。

### 3.2 股指期货大幅贴水 (IMG_0076)

| 属性 | 内容 |
|------|------|
| **对应因子** | `factor_05_futures_basis.py` |
| **原图** | 股指期货基差监控 |
| **信号含义** | 期货深度贴水 → 套保盘集中，衍生品端看空预期浓厚 |
| **触发条件** | 当月合约贴水 > 年化8% |
| **风险等级** | WATCH / ALERT |

**原理详解**：

股指期货贴水（期货价格 < 现货价格）反映了衍生品市场的看空预期。贴水扩大的机制：

1. 机构投资者（尤其是量化基金）在预期下跌时，首选卖出股指期货对冲
2. 集中卖出 → 期货价格跌幅 > 现货 → 贴水扩大
3. 贴水扩大 → 做市商对冲成本上升 → 进一步压缩做市空间
4. 做市商减少报价 → 流动性下降 → 波动进一步放大

**为什么重要**：期货贴水是衍生品端"聪明钱"的看空信号。与ETF赎回（现货端）形成交叉验证——如果两者同时恶化，说明现货和衍生品两端都在出逃。

**在V3中的代理变量**：`科创50ETF相对沪深300ETF的5日相对弱度（取负）`。当科创50持续跑输沪深300时，说明高弹性品种被抛售，类似于期货贴水恶化。

### 3.3 做市商被迫对冲 (IMG_0078)

| 属性 | 内容 |
|------|------|
| **对应因子** | `factor_03_dealer_hedging.py` |
| **原图** | 做市商对冲压力监控 |
| **信号含义** | 做市商被迫追单对冲 → 因果放大链的执行环节 |
| **触发条件** | 做市商对冲比率超过阈值 |
| **风险等级** | WATCH / ALERT |

**原理详解**：

做市商（期权/ETF）通过Delta对冲来管理风险敞口。在正常市场中，做市商的对冲行为是"逆周期"的（稳定市场）。但在极端情况下：

1. 市场下跌 → 做市商的Delta暴露增加 → 被迫卖出对冲
2. 卖出 → 市场进一步下跌 → Delta继续增加 → 更多卖出
3. 这种"正反馈"循环使得做市商从"稳定器"变为"加速器"

**为什么重要**：做市商对冲是拥挤→崩溃链条的"执行环节"。①ETF赎回是"信号"，③做市商对冲是"执行"。当执行端开始追单时，说明下跌已经不是"调整"而是"拥挤释放"。

**在V3中的代理变量**：`5日内单日绝对收益超过1.5σ的天数比例`。极端单日波动聚集 = 强迫对冲盘的迹象。

### 3.4 Gamma挤压 (IMG_0077)

| 属性 | 内容 |
|------|------|
| **对应因子** | `factor_04_gex.py` |
| **原图** | Gamma Exposure (GEX) 监控 |
| **信号含义** | 负Gamma环境 → 做市商被动追单 → 波动放大器 |
| **触发条件** | GEX转负且绝对值 > 阈值 |
| **风险等级** | ALERT (权重1.5×，核心机制) |

**原理详解**：

Gamma是期权Delta对标的资产价格变化的二阶导数。GEX（Gamma Exposure）衡量做市商整体Gamma敞口：

- **正Gamma环境**：做市商在价格下跌时买入、上涨时卖出 → 逆周期行为 → **稳定市场**
- **负Gamma环境**：做市商在价格下跌时卖出、上涨时买入 → 顺周期行为 → **放大波动**

当大量期权集中在某一行权价附近时，一旦价格接近该行权价，Gamma会急剧变化。如果此时做市商整体Gamma为负，他们的对冲行为会形成"Gamma挤压"：

```
价格下跌 → 做市商Delta增加 → 被迫卖出现货
→ 价格进一步下跌 → Delta继续增加 → 更多卖出
→ 循环加速 → 形成"闪崩"或"踩踏"
```

**为什么重要**：Gamma挤压是整个链条的**核心机制**——它是把"温和下跌"放大为"剧烈崩盘"的波动放大器。在composite_risk.py中，GEX因子的权重是其他因子的1.5倍。

**在V3中的代理变量**：`RV(20日)的5日变化率`。当RV快速上升时，类似于Gamma从正转负的波动放大效应。

### 3.5 深度虚值期权暴涨 / SKEW (IMG_0079)

| 属性 | 内容 |
|------|------|
| **对应因子** | `factor_02_skew_index.py` |
| **原图** | SKEW指数 / 深度虚值Put期权IV监控 |
| **信号含义** | 尾部对冲需求暴增 → 长期信号 |
| **触发条件** | SKEW > 145 或 深虚Put IV日增幅 > 15% |
| **风险等级** | WATCH / ALERT |

**原理详解**：

SKEW指数衡量期权市场对"尾部风险"（极端下跌）的定价：

- **SKEW = 120** → 市场认为极端下跌概率较低
- **SKEW = 150** → 市场对极端下跌的担忧显著上升
- **SKEW > 150** → 尾部风险对冲需求极端，往往是危机前兆

深度虚值Put期权（如行权价为现货90%的Put）平时几乎没有价值。但当"聪明钱"预期极端下跌时，他们会大量买入这些便宜但杠杆极高的Put：

1. 买入深虚Put → Put的IV上升 → SKEW上升
2. 做市商卖出Put后需要Delta对冲 → 卖出现货
3. 如果多个做市商同时对冲 → 下跌加速 → Put从虚值变实值

**为什么重要**：SKEW是**长期信号**（预警周期可达数周到数月），与0DTE的**短期信号**形成时间维度的互补。SKEW上升但市场还没跌 = "聪明钱在买保险"。

**在V3中的代理变量**：`20日内最大单日跌幅 / 20日RV`。极端左尾事件占已实现波动的比例，类似SKEW上行信号。

### 3.6 末日轮爆量 / 0DTE (IMG_0080)

| 属性 | 内容 |
|------|------|
| **对应因子** | `factor_01_0dte_surge.py` |
| **原图** | 0DTE（零日到期）期权成交量监控 |
| **信号含义** | 短期投机/对冲极端活跃 → 短期信号 |
| **触发条件** | 0DTE成交量占比 > 40% 且日增幅 > 50% |
| **风险等级** | WATCH / ALERT |

**原理详解**：

0DTE（Zero Days to Expiration）期权是当天到期、当天行权的期权。它们的特点：

- **时间价值极低** → 杠杆极高（可达100倍以上）
- **价格便宜** → 散户和投机资金的最爱
- **Gamma极大** → 对做市商对冲压力最大

当0DTE成交量暴增时：

1. 大量0DTE被买入 → 做市商卖出0DTE → 做市商承担极大Gamma
2. 由于0DTE的Gamma极高，做市商需要频繁对冲 → 日内波动放大
3. 如果到期日价格接近行权价 → "Gamma爆炸" → 可能引发闪崩

**为什么重要**：0DTE是**短期信号**（预警周期以天计），与SKEW的长期信号互补。0DTE爆量 + SKEW上升 = "长端和短端都在买保险" → 信号确认。

**在V3中的代理变量**：`当日成交量 / 20日均量`。成交量异常放大 = 交易需求暴增的代理信号。

## 4. 代理变量设计

由于历史期权链和资金流数据不可回测，V3在每日ETF价格数据上构建了6个**代理变量**，分别捕捉同一现象的不同侧面：

| # | 原始指标 | 代理变量 | 公式 | 捕捉维度 |
|---|---------|---------|------|---------|
| ① | ETF异常赎回 | 日内振幅比 | `(High-Low)/Close` 的20日Z-score | 日内波动放大 |
| ② | SKEW指数 | 左尾占比 | `max(0, -r) / RV(20d)` 的20日Z-score | 尾部风险占比 |
| ③ | 做市商对冲 | 极端波动聚集 | `5日内 |r-μ|>1.5σ 的天数 / 5` 的20日Z-score | 强迫对冲频率 |
| ④ | Gamma挤压 | RV加速度 | `(RV_t - RV_{t-5}) / RV_{t-5}` 的20日Z-score | 波动加速度 |
| ⑤ | 期货贴水 | 跨品种相对弱度 | `-MA5(r_kc - r_hs)` 的20日Z-score | 高弹性品种被抛售 |
| ⑥ | 0DTE爆量 | 量比 | `Volume_t / MA20(Volume)` 的20日Z-score | 交易量异常 |

### 4.1 为什么用Z-score归一化

6个代理变量的量纲完全不同（振幅是百分比、量比是无量纲、左尾占比是比值），直接加权没有意义。Z-score归一化：

1. 把每个变量转换为"距离自身均值多少个标准差"
2. 消除量纲差异，使6个变量可比
3. 正值 = 高于历史常态（压力偏高），负值 = 低于历史常态（压力偏低）

### 4.2 代理变量的局限性

代理变量是对真实衍生品信号的**低分辨率近似**：

| 代理变量 | 信息损失 | 实盘改进方案 |
|---------|---------|------------|
| 日内振幅比 | 无法区分"主动赎回"和"被动波动" | 用ETF实际申赎数据替换 |
| 左尾占比 | 混淆了"已实现"和"隐含"尾部风险 | 用真实SKEW指数替换 |
| 极端波动聚集 | 无法区分"做市商对冲"和"散户追涨杀跌" | 用做市商持仓数据替换 |
| RV加速度 | 只能捕捉已实现的Gamma效应 | 用真实GEX数据替换 |
| 跨品种弱度 | 只能反映现货端分歧 | 用真实期货基差替换 |
| 量比 | 无法区分"投机"和"对冲" | 用0DTE成交量占比替换 |

## 5. 复合压力得分 (CSS) 算法

### 5.1 算法流程

```
输入: 科创50ETF日K线 (OHLCV) + 沪深300ETF日收盘价

Step 1: 计算6个代理变量
  ① etf_anomaly  = proxy_etf_anomaly(high, low, close, window=20)
  ② skew_proxy   = proxy_skew(returns, window=20)
  ③ dealer_hedge = proxy_dealer_hedge(returns, window=20)
  ④ gex_proxy    = proxy_gex(returns, window=20)
  ⑤ basis_proxy  = proxy_futures_basis(kc_close, hs_close, window=20)
  ⑥ vol_ratio    = proxy_0dte(volume, window=20)

Step 2: Z-score归一化
  z_i = (x_i - mean(x_i)) / std(x_i)   # 对每个序列独立计算

Step 3: 等权平均
  avg_z = (z_1 + z_2 + z_3 + z_4 + z_5 + z_6) / 6

Step 4: 映射到0-100
  CSS = clamp(50 + avg_z * 25, 0, 100)
  # z=0 → CSS=50 (中性)
  # z=+2 → CSS=100 (极端压力)
  # z=-2 → CSS=0 (极端平静)

输出: CSS ∈ [0, 100]
```

### 5.2 体制分类

| CSS得分 | 体制 | 操作 |
|---------|------|------|
| < 35 | **Calm (稳定)** | 买入科创50ETF（追求弹性） |
| 35 - 75 | **Transition (过渡)** | 持仓不动 |
| > 75 | **Crisis (危机)** | 轮动到中证1000ETF（缓冲） |

### 5.3 为什么等权而不是加权

在composite_risk.py的标准实现中，GEX因子的权重是其他因子的1.5倍。但在V3回测中使用等权，原因：

1. 代理变量本身就有信息损失，加权可能放大噪声
2. 等权更简单，符合"简单胜复杂"的理念
3. 参数敏感性测试显示，等权的Top 5参数组合收益差异 < 1%，鲁棒性好

实盘建议：用真实衍生品数据后，恢复GEX 1.5×权重。

## 6. 策略规则

### 6.1 入场条件

| 条件 | 科创50ETF入场 | 中证1000ETF入场 |
|------|-------------|----------------|
| CSS | < 35 (Calm) | > 75 (Crisis) |
| 趋势过滤 | close > MA20 | 无 |
| 冷却期 | 已过 | 已过 |

### 6.2 止损规则

| 止损类型 | 规则 | 说明 |
|---------|------|------|
| 跟踪止损 | max(历史最高价 - 2.5×ATR(14), ...) | ATR倍数经网格搜索优化 |
| 硬止损 | 入场价 × (1 - 8%) | 强制底线 |
| 执行优先 | 两者先触发先生效 | 盘中触及即执行 |

### 6.3 冷却期

止损触发后，等待5个交易日再评估新入场信号。目的：
- 避免在波动高峰期连续止损
- 让概率优势稳定发挥
- 符合"执行优先于信号"的理念

### 6.4 仓位管理

简化版：满仓进出（100%仓位）。实盘建议：
- 单笔仓位不超过总资金50%
- 留50%现金应对极端情况
- 可用凯利公式动态调仓

### 7.3 参数敏感性

网格搜索了 3×4×4×1 = 48 组参数组合：

| 参数 | 搜索范围 | 最优值 | 敏感性 |
|------|---------|--------|--------|
| calm_max | 30/35/40 | 35 | 低（30→40 收益变化 < 6%） |
| crisis_min | 65/70/75/80 | 75 | 极低（65→80 收益变化 < 1%） |
| atr_multiplier | 2.5/3.0/3.5/4.0 | 2.5 | 中（2.5→4.0 收益下降约7%） |
| hard_stop_pct | 8% | 8% | 固定 |

**结论**：crisis_min在65-80区间收益几乎不变，说明策略对参数不敏感——这正是简单策略应有的鲁棒性。

### 9.2 实盘使用

1. **每日收盘后**：获取科创50ETF和沪深300ETF的日K线数据
2. **计算6个代理变量**：参见 `strategy_backtest_v3.py` 中的 `proxy_*` 函数
3. **计算CSS**：6个Z-score等权平均 → 映射到0-100
4. **执行决策**：
   - CSS < 35 且 close > MA20 → 持有科创50ETF
   - CSS > 75 → 轮动到中证1000ETF
   - 35-75 → 持仓不动
5. **检查止损**：每日盘中检查2.5×ATR跟踪止损和-8%硬止损
6. **冷却期管理**：止损后5个交易日内不做新入场
